# ADR 0002 — 用户三裁决：NTU 验证纳入 / 合成数据口径缓议 / E6 依据时限确认

> 背景: 规划会话换防后挂起的三项决策（见 `docs/paper/review-log.md` 投稿就绪门 + W6 报告 §8 移交项）

## 裁决 1：NTU 复现验证行 ✅ 纳入 P0 范围

- **内容**：在本仓环境复现 AimCLR 原文参照成绩，证明适配实现与官方等价（风险登记册 R4 缓解）。
- **⚠️ 执行前置（本会话补充核查发现）**：本仓**无 NTU 数据**（`DATA_LOCATIONS.md` 三数据集均不含 NTU）。执行需先取得 NTU60 骨架版数据（公开下载约 6GB 量级 + AimCLR 官方预处理流程），属增量工程。
- **排程裁决**：P0.2 救援（GPU 占用中）结束后开独立小窗口执行；不插入 W8（其零 GPU 依赖设计不被破坏）。
- 状态：已批准，待排程 → 同步至 `experiment-skeleton.md` §4.4 与 outline 风险登记册 R4。

## 裁决 2：路径 a 合成数据磁盘口径 → **缓议（方案 A：推迟到触发点）**

- **问题原貌**（白话版）：论文和验收的最终目标是 22 类行为。我们现在的种子只有 7 个物理动作类（坐/走/站/跑/跳/起身/卧）。要从 7 类扩到 22 类，需要 K9 仓那套"合成数据生成管线"产出一批带 22 类标签的骨架数据。W6 去看了两个候选目录，没找到现成的骨架集——所以需要用户说清"这数据在哪/能不能重新生成"。
- **用户委托最优决策，裁定如下**：
  1. **现在不做任何事**。P0.3 Phase A 在 7 类物理先验体系上验证方法有效性（这不影响论文方法主张，方法创新在管线不在类数）。
  2. **触发点写死**：P0.5 微调开工前。届时二选一：(a) 授权本仓按 `docs/assets-map.md` 流显式移植 K9 合成数据生成器并本地重建；(b) 用户提供 K9 仓现有合成骨架集的确切路径登记入 `DATA_LOCATIONS.md`。
  3. 若届时两条路都不通，回退预案：论文口径改为"7 类物理先验体系验证"，22 类主张降级为讨论段——该变更影响 stage-plan 验收线（≥85%/22 类），须再次经用户确认。
- **对用户的承诺**：此决策在 P0.5 开工前会被交接文档自动重新提起，不会静默遗忘。

## 裁决 3：E6 演化场景业务依据 → 时限确认，候选场景先行预注册

- 用户确认"P0.5 前给"。为避免临场拍脑袋，规划会话预注册候选场景（P0.5 前最终对齐即可）：
  - **Y′ 候选**：基于真实运营粒度变化——把 standing/walking 合并为 locomotion（粗报场景）、把 jump 拆分为 jump_up/jump_down（精细考核场景）。动机可引用工作犬项目调整考核标准的行业实践 [CITATION-NEEDED: 行业文献]。
  - 该候选满足 experiment-skeleton E6 的"非作者自造"要求（对应真实业务粒度需求变化），但**正式采用前仍需用户一句话确认**。
